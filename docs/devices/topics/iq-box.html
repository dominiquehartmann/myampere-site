Previous EKD smartbox ("IQ box") and the EKD cloud

Not official information. Compiled by the OpenAmpere contributors; can be incomplete or wrong. No affiliation with EKD or the manufacturers named here, not legal advice. See Device knowledge.

Applies to: the energy manager ("smartbox", "IQ box") installed with the storage systems sold by EKD, the EKD cloud behind it, its customer API and the previous app · Sold as: part of "Ampere.StoragePro" and "Ampere.StoragePro E3" systems · OpenAmpere: no driver, OpenAmpere never talks to the box; it detects the box's effects (control.py, diagnostics.py, drivers/modbus.py) and imports the cloud history (cloud_import.py) · Support: – · Confirmed on a real device: partly

The name "IQ box" or "smartbox" is used here only to describe the device. App texts call it the "former smartbox" without a manufacturer name.

Summary

  • While it is connected, the box fetches its target settings from the EKD cloud about every 100 seconds and writes them to the inverter. Changes made in OpenAmpere (backup reserve, work mode, grid charging, export limit) jump back.
  • Owners stop this by blocking the box's internet access in the router, or by disconnecting the box if nothing else needs it (for example control by the grid operator).
  • On a FoxESS H3 the box holds one of the very few Modbus TCP connections all the time.
  • While it is powered, OpenAmpere cannot read the FoxESS AC EV Charger that came with the system (#431).
  • On a FoxESS H3 it uses the inverter's remote control with its own values (enable 5, timeout 30 s), which is how OpenAmpere tells it apart from its own commands (1 or 5 with 180 s; since OpenAmpere writes 5 as well, by the timeout, #509).
  • On an SAJ it writes the work mode and the reserve, and while charging from the grid an undocumented block at 0x8300 every 1–3 s.
  • The EKD cloud's customer API blocks clients that poll too often; OpenAmpere's history import sends at most one request per 65 s.
  • No source shows that an inverter stops when the box is switched off for good; the box has no watchdog role in any document found. SAJ owners report their system running on without it; on a FoxESS H3 only short-term reports exist. The real risk is cutting the box off in the middle of one of its commands (see Behaviour).

Behaviour

The box and the inverter

FactStatusSource
The box fetches its target settings from the EKD cloud about every 100 s and writes them to the inverter, overwriting changes made by OpenAmpere (backup reserve, work mode, grid charging, export limit). Seen repeatedly in owners' questions.confirmed#25, #53, #373, #374
Blocking the box's internet access in the router stops the resets: an owner kept a changed backup reserve and a switch to price-based grid charging.confirmed#25, #53
With its internet access blocked, the box keeps reading along but gets no targets and no updates, and the manufacturer's app shows no current data.derived#25, #53
On a FoxESS H3 the box keeps its own Modbus TCP connection open all the time and does not release it, so it can take one of the inverter's very few connection slots. OpenAmpere's "per poll" connection mode does not help against it.confirmed#311, #312
The box is also configured as a Modbus TCP client of the FoxESS AC EV Charger ("Ampere.ChargePro Bridge", host EVC-<serial>.local, unit id 1, port 502, not configurable on its settings page). While the box is powered, OpenAmpere cannot read the charger; with the box cut from power the wallbox check reads it at once. Whether the charger allows only one client or mishandles concurrent clients, and whether the box also controls the charger, is open; see ac-charger.md.configured as a client: derived; blocks access: confirmed (one device)an owner's screenshot of the box's settings page, #427; owner's diagnostics report, #431
On a SAJ 0x005E OpenAmpere ("Nur ansehen", connection mode "per poll") read live values over Modbus TCP for days while the box stayed connected and controlled the system, also while the box had no cloud connection for about two hours. On another 0x005E the box blocked OpenAmpere (#469); why the two differ is open.confirmed (one SAJ)owner report in #576
Disconnecting the box from the network (its LAN cable or its power, not the inverter's) frees the slot.confirmed#311
At one installation that routed everything through a Modbus proxy, the box set itself back to the inverter's own address after a while and took a slot again. A proxy is no lasting way to share the inverter with the box.confirmed#311, #312
After the box is disconnected, the inverter keeps working with the settings stored last. SAJ: owners report the system running on with the box switched off (the battery went on discharging) or never having had a box. FoxESS H3: only reports of the first hours after cutting the box off, no long-term report.confirmed (SAJ, owner reports), open (FoxESS long-term)owner reports in a Photovoltaikforum thread on bursts of discharge, page 11 of a Photovoltaikforum thread on the storage and a Home Assistant community thread; #311, #312, #469
Neither inverter has a documented function that stops or limits it when an external controller such as the box falls silent. Kiwigrid's installation guide for the Energy Manager RailX (version 014, 2025) mentions no watchdog, fallback or loss of communication for connected inverters or batteries. FoxESS's only mechanism is the timeout of the remote control (see below); SAJ has none (see h2-family.md).documented (none in the documents named)Kiwigrid, installation guide Energy Manager RailX, version 014; FoxESS Modbus interface definition V1.05.04.00; SAJ H2 protocol
The grid meter is read by the inverter (its values are in the inverter's registers), not by the box, so self-consumption and the export limit do not depend on the box. FoxESS reports a lost meter as an alarm ("Meter Lost"); on the FoxESS H1 a lost CT switches the inverter off, for the H3 this is not documented. Whether any EKD installation wires the meter through the box is open.deriveda Home Assistant community thread (SAJ meter registers); FoxESS Modbus interface definition V1.05.04.00; FoxESS H1/AC1 G100 declaration
The export limit stays in force without the box: it is stored in the inverter and works with the meter the inverter reads itself (row above). No owner report shows it from a device.derivedfoxess/h3.md, saj/h2-family.md; #311, #312
FoxESS: per FoxESS's Modbus definition 46001 is a bit field (bit 0 on, bits 3:2 target: 00 AC, 01 battery, 10 grid, 11 AC with grid first). The box's 5 therefore means remote control on with the battery as target. The FoxESS definition does not say what happens when the timeout ends; foxess_modbus expects the remote control to end and the inverter to go back to its own work mode, so the box's 30 s timeout would end it soon after the box falls silent. If it stays on as in #141, the battery would stay at the box's last power (0 W or charging) while PV and the house supply go on. Not seen on a device.documented (bit field), derived (behaviour)FoxESS Modbus interface definition V1.05.04.00, table 3-8 (bit field); nathanmarlor/foxess_modbus (behaviour after the timeout); foxess/h3.md
SAJ: when the box writes 0x8300 at the start of a charge, the work mode 0x3647 changes to 3 (passive mode) by itself; the box ends a charge with 0x8300 = 0 and 0x3647 = 0 written back to back. Cut off in the middle of a charge, the inverter may therefore keep passive mode and the reserve 0x3644 at 100 %, and the battery would not discharge until someone changes them.derivedstanus74/home-assistant-saj-h2-modbus#18 (recorded traffic); #377
The box may be needed for something else, for example control by the grid operator (§ 14a EnWG for a controllable device such as a wallbox or heat pump, § 9 EEG for feed-in). It can only do that where a smart meter gateway with a control box at the meter exists and is connected to the box (a cable on its inputs, or EEBus in the home network). No installation has confirmed it either way; owners check it with the steps in the README before disconnecting the box.open (depends on the installation)#25, #311, #452
FoxESS: the box drives the remote control with 46001 = 5, 46002 = 30 s, its charge power in 46003–46004, and also writes 20162 = 1.confirmed (owner's report)#141, #142
FoxESS: a remote control that is on with values other than OpenAmpere's usually means the box is following targets from its cloud; it can overwrite grid charging and battery settings.derived#126, #127, #136, #142
SAJ: the box writes the work mode 0x3647 and the on-grid reserve 0x3644. It can switch an SAJ away from time-of-use mode while OpenAmpere charges through a charge slot.derivedstanus74/home-assistant-saj-h2-modbus#18; #382, #383
SAJ, grid charging by the box: it sets 0x3644 to 100, then writes 0x8300–0x8306 with FC16. From the grid only, every 3 s, with values in the pattern 3, 2, about the charge power, …, 600, 10000, 10000. With PV, 0x8300–0x8304 every second. At the end it writes 0x8300 = 0 and 0x3647 = 0 and puts 0x3644 back.derivedstanus74/home-assistant-saj-h2-modbus#18 (recorded traffic); research in #377

The EKD cloud and the previous app

FactStatusSource
The EKD cloud (behind the Ampere.IQ app) has a customer API that EKD documented for customers at developer.ekd-solar.de; access uses a personal key from the owner's app.documentedEKD's customer API documentation; README
The customer API blocks clients that poll too often. Requests carry a fixed client type value (de.ekd.customer.apiclient) that the API requires.documentedEKD's customer API documentation; cloud_import.py
The history can be fetched in two steps: energy values in quarter hours, then the battery state of charge per day.confirmed#17, #42
The previous app apparently calculated house consumption as the balance of the other energy flows, so its value differed from the inverter's own consumption counter.derived#15, #36; see Open questions
The previous app offered three grid charging levels at 50, 75 and 100 % of the charge power the battery's datasheet permits.derived#23, #49
In September 2025 EKD switched off the storage function of the older "AMPERE.Storage" (SolarMax-based, neither SAJ nor FoxESS) remotely, announced one day before and citing a regulatory component to be retrofitted. EKD released it again after a fuse was fitted on site in the following weeks. This has nothing to do with switching the box off, but may be where the story "the system stops by itself" comes from.confirmed (owner reports), derived (link to the rumour)owner reports in a Photovoltaikforum thread on the shutdown
The box is a Kiwigrid energy manager. In the LAN it offers a REST interface (items named after the inverter, e.g. sajhybrid_… or foxesshybrid_…); it has no Modbus server of its own, but is a Modbus TCP client of the inverter and the charger (see above).derivedevcc-io/evcc discussion 8394; Photovoltaikforum on the Ampere Storage Pro; names.md

Open questions

  • What FoxESS register 20162, written as 1 by the box, means (#141).
  • Whether the SAJ block 0x8300–0x8306 ends by itself when the writes stop; 0x8304 = 600 might be a timeout in seconds (assumption, stanus74/home-assistant-saj-h2-modbus#18, #377).
  • Whether the inverter keeps exactly the last settings after the box is disconnected; no owner has reported it yet (#312).
  • Conflict about the consumption value: #15 says the previous app's balance was higher than the inverter's consumption counter, while #346 found the inverter's counter about 50 % higher than the balance, which the manufacturer's app showed. Possibly different devices or apps; see modbus.md.
  • Whether the box acts as the energy manager (HEMS) for the grid operator: it would get "reduce power" from the smart meter gateway through a control box at the meter, confirm it and limit the system until the end of the reduction. Public sources describe this path (the signal goes from the gateway's CLS channel to a control box and from there to an HEMS or straight to the device, today mostly through relay contacts, a digital interface such as EEBus or Modbus as a next step), but nothing shows that the box does it. Kiwigrid presents taking these signals from the gateway as new with its RailX+ (2026), which makes it less likely for the older box (derived). Hypothesis, status open (#452).
  • Whether a FoxESS H3 runs normally for weeks without the box, and whether the box's remote control (5/30 s) ends by itself when the box is cut off in the middle of a command.
  • Whether any EKD installation wires the grid meter through the box instead of to the inverter.
  • Whether and when the EKD cloud will be switched off (#84).
  • The ZIP edge cases above come from reviews, not from a real export (#288).
  • Whether the box only reads the FoxESS AC EV Charger or also controls it, and why the charger cannot be read while the box is powered (only one client, or concurrent clients mishandled; #431).
