go-e Charger

Not official manufacturer information: compiled by the OpenAmpere contributors, can be incomplete or wrong. No affiliation with go-e or EKD; not legal advice. See the device knowledge README.

Applies to: go-e Charger wallboxes (HOME, Gemini and later; older hardware only through API v1) · Sold as: go-e Charger (not sold by EKD) · OpenAmpere: wallbox module goe (src/openampere/wallbox/goe.py) · Support: display only (live view, found by the search in the wallbox setup) · Confirmed on a real device: no (built from go-e's public API descriptions and the simulator)

Summary

  • The go-e Charger has a local HTTP API on port 80, without a login. It is off until the owner switches it on in the go-e app: API v2 on newer hardware, API v1 on all hardware (the only one of the oldest).
  • OpenAmpere asks GET /api/status with a filter (API v2) and, if that gives no go-e answer, GET /status (API v1). It only sends these two GET requests: no /api/set, no /mqtt, so it never changes the charger.
  • It shows the state, the power, current and voltage per phase, the energy and (API v2) the duration of the charge, the current offered to the car and the highest current. Only the mode "manual".
  • Modbus TCP, MQTT and OCPP exist as well, but are also off by default; OpenAmpere does not use them yet.
  • Control (solar charging) is a separate step with its own issue: it needs the safety rules for writing, and what the charger does when OpenAmpere is gone has to be settled first.

Keys read

API v2: GET http://<address>/api/status?filter=car,nrg,wh,amp,ama,fwv,cdi. API v1: GET http://<address>/status (the whole status, values as strings).

Decisions in OpenAmpere

DecisionWhyIssue/PR
HTTP API (v2, then v1), not Modbus TCP.Works on all hardware, needs no restart of the charger, is what owners already switch on for evcc and other tools, and uses only the Python standard library (no new dependency).#597
Display only: only GET of the status, only the mode "manual"; its power counts in the house load like any wallbox.Nothing confirmed on a real device; control needs its own safety rules first.#597
The search in the setup tries port 80 of every address in the local networks and keeps those whose status answer looks like a go-e (keys car and nrg).No multicast needed, so it also works in the Home Assistant app; a device without the API switched on is not found, and the app says to switch it on.#597
A voltage above 400 V, a current above 80 A, a power above 30 kW or a charge above 200 kWh is not shown; with such a power the state is unknown.A wrong unit would give such values: better no value than a wrong one.#597
The total energy (eto) and the serial number (sse) are not asked for.Not needed for the live view; an exact counter or serial identifies the owner.#597
No redirect is followed and no proxy used.The charger is in the home network.#597

Open questions

  • The units of API v2 (nrg in V, A, W) on a real charger, and the values while it charges on one phase.
  • Whether a charge with "waiting for the car" (car 3) should show as waiting rather than plugged in.
  • What cdi holds after a charge ends, and whether wh keeps the last charge after the car is unplugged.
  • What firmware before 051.4 answers to the filter (OpenAmpere then falls back to API v1, which has to be on).
  • Whether the charger answers reliably to two readers (evcc and OpenAmpere) every 10 s.
