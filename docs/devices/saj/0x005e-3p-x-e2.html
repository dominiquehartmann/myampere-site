SAJ type code 0x005E, "3P-X E2"

Not official manufacturer information: compiled by the OpenAmpere contributors, can be incomplete or wrong. Changing inverter settings can affect the warranty and grid rules; no affiliation with SAJ or EKD; not legal advice. See the device knowledge README.

Applies to: SAJ inverters reporting type code 0x005E in register 0x8F00 · Sold as: "Ampere.StoragePro" (EKD) · OpenAmpere: driver saj, register map saj_h2 · Support: display and control (since 0.29.0) · Confirmed on a real device: partly (identification, live values and battery limits; in daily use by an owner; of OpenAmpere's writes only the on-grid depth 0x3644)

Everything this type shares with the H2/HS2 family (registers, behaviour, grid charging, export limit, decisions) is on h2-family.md. This page holds only what is specific to 0x005E.

Summary

  • 0x005E is not in SAJ's H2 protocol, which lists 0x0055–0x005D. The name "3P-X E2" comes from the manufacturer's app of an owner.
  • A three-phase type, sold by EKD as "Ampere.StoragePro".
  • Read with the H2 map; detection, live values and the battery limits worked on a real device.
  • Control is enabled because its settings registers matched the manufacturer's app (#334).

Behaviour

FactStatusSource
The manufacturer's app shows this type as a three-phase "…-3P-X E2" model together with a power class, as given by an owner.confirmed#339
The type is sold by EKD as "Ampere.StoragePro".confirmed#339
0x005E lies inside the family range 0x0050–0x006F, so detection worked before it had a name: the log warned about an unknown SAJ device type and the app showed "Typ 0x005E". Live values and battery limits read correctly with the H2 map.confirmed#334, #339, #379
The settings registers 0x3644–0x3647 matched the manufacturer's app; this is where the right mapping of the on-grid and off-grid limits was found (see h2-family.md).confirmed#334, #335, #337
A second owner confirmed detection and live values on this type with the Docker installation, after cutting the previous IQ box from the network (see h2-family.md).confirmedowner report by e-mail, summarised in #469
An owner uses OpenAmpere on this type in daily operation and is satisfied. Whether control was switched on, and which writes were made, is not recorded.confirmed (daily use), open (writes)an owner's report, 2026-10
With control switched on (0.35.0), changing the "Notstrom-Reserve" in the app by a few percent wrote the on-grid depth 0x3644; the inverter accepted it and OpenAmpere read the new value back. Whether the battery stops discharging at the new value has not been observed yet.confirmed (write and read-back), open (discharge limit)owner report by e-mail, summarised in #601
With a second inverter at Meter B, the inverter's house power 0x40A0 matched the balance (grid + PV + Meter B + battery) only with the battery idle; while the battery charged or discharged it was far off. OpenAmpere takes the live house power from the balance (see h2-family.md).derived#576
The live house power from the balance (since 0.38.0) agreed within 0.01 kW with the owner's own balance of the values the app showed, with grid import, while the battery discharged and while it charged; before, 0x40A0 was off by up to about 1 kW. The daily energy values (PV, consumption, grid import and export, battery charge and discharge, self-sufficiency), compared on 0.37.0, matched the previous IQ box within its rounding; they already came from the balance (#346), not from 0x40A0.confirmed#576
On another 0x005E OpenAmpere ("Nur ansehen", connection mode "per poll", a reading every 30 s) read live values over Modbus TCP for days while the box stayed connected and controlled the system, also for about two hours in which the box had no cloud connection. Why it worked there and not on the device of #469 is open. See h2-family.md and iq-box.md.confirmed (one 0x005E)owner report in #576
Being three-phase, the summed grid counters 0x4167 ff. are the ones that cover all phases.derived#379
Every night in the early morning the inverter reports a fault for about ten minutes and then runs normally again. OpenAmpere saw the fault word value 0x800000 (bit 23); its meaning and the cause (a restart or self-check is suspected) are unknown. Reported by several owners and in owners' forums.open#404

Decisions in OpenAmpere

DecisionWhyIssue/PR
0x005E is named "3P-X E2", without the power class; the rated power is read from 0x8F01. Without a class to check it against, the export limit waits for the owner's confirmation of the rated power (#492).One type code covers several power classes (0x005B covers 5 to 10 kW).#339, #379, #492
Control is enabled for 0x005E (battery settings, export limit, grid charging), as for the H2 and HS2.Its settings registers matched the manufacturer's app.#334, #378
The summed grid counters are used when the device answers them, otherwise L1 (same rule as the family).Three-phase: L1 alone would miss two phases.#379
A fault is notified only after it has lasted 30 minutes (all devices).The nightly fault of this type sent a false alarm every morning; a real fault still lasts.#404

Open questions

  • Whether a 0x005E answers the summed grid counters 0x4167 ff. on every firmware is not recorded.
  • Whether the battery stops discharging at an on-grid depth 0x3644 written by OpenAmpere (#601).
  • OpenAmpere's other writes (0x3645–0x3647, 0x3651, export limit, charge slot) are not yet confirmed on a 0x005E (#378).
  • What the nightly fault is (fault bit 23, about ten minutes in the early morning): the running mode 0x4004 and the three fault words during the event are not recorded yet (#404).
  • The open questions of the family apply as well: h2-family.md.
