FoxESS H3, register map of older firmware

Not official manufacturer information: compiled by the OpenAmpere contributors, possibly incomplete or wrong. Changing inverter settings can affect warranty and grid connection rules. No affiliation with FoxESS or EKD, not legal advice. See Device knowledge.

Applies to: classic FoxESS H3 with older firmware · Sold as: not stated in the sources (see h3.md) · OpenAmpere: driver foxess, register map foxess_h3_legacy · Support: display and control (no export limit) · Confirmed on a real device: no

Family facts (detection, connection limits, remote control behaviour, decisions on grid charging) are on h3.md; the newer map is on h3-new-map.md.

Summary

  • Chosen when the new map's counters (39601) do not answer but the counters at 32000 do. Measurement registers are holding registers (FC03) by default; OpenAmpere falls back to FC04.
  • No total registers for grid and house: OpenAmpere adds up the three phases. Only two PV inputs.
  • Energy counters in 0.1 kWh; daily values are 16-bit.
  • Settings at 41000–41011 (read each register on its own; some addresses in this range are invalid), remote control at 44000–44003. No known export limit register.
  • Nothing on this map is confirmed on a real device yet, neither reading nor control.

Registers

Read in blocks (start + count): 31000+52, 31090+1 (optional), 32000+24. Addresses inside a block that are not listed below are read but not used. Model string 30000–30015: see h3.md. All registers here are holding registers.

Behaviour

FactStatusSource
There is no total register for grid or house power, only the three phases; and only two PV inputs.derivednathanmarlor/foxess_modbus; docs/registers.md, docs/devices.md
Registers in the 41xxx range must be read one at a time; 41001–41006, 41012–41013 and 41015 are invalid.derivednathanmarlor/foxess_modbus; docs/registers.md
No register for the export limit is known on this map.deriveddocs/registers.md, docs/devices.md
The remote control block (on/off, timeout, power) sits at 44000–44003, the counterpart of 46001–46004 on the new map.derivednathanmarlor/foxess_modbus; #127
The energy counters count in 0.1 kWh (100 Wh) steps, so counter-based energy has no meaningful second decimal.derivednathanmarlor/foxess_modbus; #194, #195
Battery health (31090) needs firmware 1.80 or newer.derivednathanmarlor/foxess_modbus; docs/devices.md

Decisions in OpenAmpere

DecisionWhyIssue/PR
Grid power = −(31026 + 31027 + 31028) (+ = import), house power = 31029 + 31030 + 31031, PV power = PV1 + PV2.No total registers on this map.driver.py

The FoxESS detail checks of the diagnostics (optional blocks, block reads, temperature scale, export limit, remote control) run only for the new map. The background job that watches the remote control (read-only, every 5 minutes) reads 44000–44003 on this map too.The detail checks are built on new-map addresses.diagnostics.py

Open questions

  • Reading and control on this map are not confirmed on a real device (#111, #185, #196, #197). A diagnostics report from an H3 with older firmware would help.
  • Whether the remote control at 44000–44003 behaves like the new map's (watchdog, values left on after it, #141), and whether 44000 is the same bit field as 46001 on the new map (bit 0 on, bits 3:2 target; FoxESS's definition names only 46001).
  • Whether the work mode values (0, 1, 2, 4) and the SoC limits behave as documented.
  • Whether any firmware of this map has an export limit register.
