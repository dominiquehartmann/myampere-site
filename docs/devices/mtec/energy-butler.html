M-TEC Energy-Butler GEN3

Not official manufacturer information: compiled by the OpenAmpere contributors, can be incomplete or wrong. No affiliation with M-TEC, Solinteg or EKD; not legal advice. See the device knowledge README.

Applies to: M-TEC Energy-Butler GEN3 hybrid inverters (a Solinteg inverter, also sold as Wattsonic, Sunways, A-Tronix, SunEnergyBox) · Sold as: M-TEC Energy-Butler (EKD from late 2022) · OpenAmpere: driver mtec (src/openampere/drivers/mtec/), register map mtec_gen3 · Support: display only · Confirmed on a real device: no (built from M-TEC's register document, open projects and the simulator)

Summary

  • Read through the Wi-Fi/LAN module: port 502 on newer module firmware (V27.52.4.0 and later), 5743 before.
  • Unit id and framing differ between the sources: OpenAmpere tries plain Modbus TCP, then RTU frames over TCP, on units 252, 255 and 247, and shows the one that answered in the register map (mtec_gen3 (socket) or (rtu)).
  • Holding registers (FC03), 32-bit values with the high word first; energy counters in 0.1 kWh, so OpenAmpere has an energy history for this device.
  • Signs: grid power is + for export (turned around), battery power + for discharging (as OpenAmpere).
  • M-TEC still serves owners (app and portal); OpenAmpere only reads.
  • GEN2 uses other addresses (4xxxx) and is not covered; the GEN3 registers need inverter firmware 3.04.01 or later.

Identification

  • Type plate: "Energy-Butler 10kW-3P-3G25" (three-phase, GEN3); from 2023-07 the 10 kW model is "3G40", so EKD's units from 2022/23 are most likely 3G25 (derived: M-TEC datasheet 2025, owners' posts).
  • GEN2 has RS485 only and the 4xxxx registers (documented: M-TEC document).
  • Firmware on the display, in the app or in 10011–10014.

"M-TEC document" is "M-TEC Energy Butler RTU Protocol GEN2 + GEN3 V1.0" (2022-11-19), which an owner posted publicly in the ioBroker forum; facts only, in own words. It describes RS485 (9600 8N1, address 247) and the function codes 03, 06 and 16, but lists every register as read-only.

Decisions in OpenAmpere

DecisionWhyIssue/PR
Display only: every write method refuses, supports_control is off.Nothing confirmed on a device; the writes known have no watchdog.#520
Detected after FoxESS, SAJ and Solarmax on units 252, 255 and 247; plain Modbus TCP first, then RTU frames over TCP, one try each. In the automatic detection (setup scan), if the first unit answers in neither framing, the others are asked in plain Modbus TCP only for 10 minutes; when the owner chooses M-TEC in the setup, every unit gets both framings. A device counts as an M-TEC only with a readable serial number, a known running state and a state of charge within 0–100 %.The sources disagree on unit id and framing; detection must not claim another device, and a silent Modbus device in the network must not hold up the setup scan. An RTU gateway at 247 is found when M-TEC is chosen.#520, #534
The port is not probed: with older module firmware the owner enters 5743 (the setup says so next to the port).Detection stops when nothing listens on the port; a second port would need a second address in the settings.#520, #534
Blocks only over the addresses the sources list.A block across an undocumented gap might be refused.#520
Running state 3 (fault) reports the fault flags as a fault; 5 means off-grid.M-TEC document.#520

Open questions

  • On port 502: which framing and unit id answer on an EKD unit; does 5743 still answer after an update?
  • The signs of 11000 and 30258, and whether 11016 − 11000 matches the house load in the M-TEC app.
  • Whether loads on the backup (EPS) output are part of 11016: if not, the house load needs 30230 too (and during an outage it is all of it). The diagnostics show 30230 so a report can tell.
  • Whether the module takes OpenAmpere next to the M-TEC app and cloud without trouble.
  • Type plate text ("Energy-Butler 10kW-3P-3G25" is expected) and register 10008 of an EKD unit; whether any is a GEN2.
